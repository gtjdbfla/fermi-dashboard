# 페르미(FRMI) 펀더멘탈 대시보드

Fermi Inc. (NASDAQ/LSE: FRMI, Fermi America / Project Matador)의 펀더멘탈 상태를
전력인프라 개발사업 관점에서 점검하는 Streamlit 대시보드.

## 화면 구조는 검증 결과를 따른다

처음에는 펀더멘탈을 7개 축으로 나눴지만, 그 축들이 실제로 결과를 갈랐는지는 검증하지 않은 상태였다.
매출보다 먼저 대규모 인프라를 지은 전력·에너지 상장사 **13곳**을 놓고, 결과를 주가가 아니라 객관적
재무 사건으로 유지(6)/진행중(3)/붕괴(4)로 나눈 뒤(주가로 나누면 순환논증이 된다) 항목별 값을 대조했다.
**7개 축 중 3개는 판별력이 없었다.**

| 항목 | 유지 그룹 | 붕괴 그룹 | 판정 |
|---|---|---|---|
| 자금여력(런웨이) | 평균 9.0개월 | 평균 7.2개월 | ❌ 판별 실패 |
| 자본투입(이자 자본화) | 누적 $1,251M | 누적 $31M | ❌ 판별 실패 (규모 반영일 뿐) |
| 조달 경로(차입 비중) | 69% | 51% | ⚠️ 약함 (New Fortress 반례) |
| **계약 커버리지** | **70~92%** | **0% 또는 만기 불일치** | ✅ 판별 성공 |
| **영업현금흐름 전환** | **전원 도달** | **미도달 또는 역전** | ✅ 판별 성공 |
| **단위경제성** | 매출↑ 시 현금↑ | 매출↑ 시 현금↓ | ✅ 판별 성공 |

Cheniere는 최대 지출 해에 런웨이가 **2.8개월**이었는데 살아남았고, New Fortress는 차입 83.6%로
조달하고도 붕괴했다. 그래서 판별에 실패한 항목은 **참고 지표** 탭으로 내리고, 살아남은 지표만
맨 위 핵심 판정에 둔다. 근거는 `data/axis_validation.csv`와 `sector.py`에 있다.

주가 결과도 두 그룹이 겹치지 않는다 — 유지 그룹은 고점 대비 평균 -26.4%(최악 -41.7%),
붕괴 그룹은 평균 -97.4%(최선 -96.3%).

## 왜 일반 지표를 쓰지 않는가

페르미는 매출이 0인 개발단계 회사다(2026 Q2 기준 pre-revenue). PER·PBR 성장률·영업이익률은
계산되지 않거나 계산돼도 의미가 없다. 대신 전력인프라 개발사업에서 실제로 생존과 가치를 결정하는
7개 축으로 나눠 본다.

| 탭 | 질문 | 지표 |
|---|---|---|
| **핵심 판정** (상단 고정) | 계약이 투입에 선행했나 · 계약 기간이 부채 만기를 덮나 · 현금흐름은 도는가 | 검증을 통과한 3개 |
| ① 계약 커버리지 | 지을 용량을 사 줄 고객이 계약돼 있는가 | 계약 MW/반입 MW, 섹터 벤치마크, 확정도별 MW |
| ② 현금흐름 전환 | 가동 후 현금이 실제로 들어오는가 | 분기 영업CF, 섹터의 T0→흑자 연수, 마일스톤 |
| ③ 섹터 검증 | 이 항목들이 실제로 결과를 갈랐는가 | 13개사 표본, 항목별 판별력, 주가 결과 |
| 참고 지표 | 판정에서 내린 항목들 | 런웨이 · 이자 자본화 · 희석 · 지배구조 · P/B |
| 원본 데이터 | 출처와 XBRL 원본 | 태그별 분기 시계열 |

판정 임계값은 `fundamentals.THRESHOLDS`에 코드로 드러나 있다.
정보 정리 목적의 도구이며 투자 권유나 자문이 아니다.

## 실행

기존 `stock_dashboard`의 가상환경을 그대로 쓴다(streamlit·pandas·plotly·requests가 이미 있다).

```bash
C:/Directory/claude/stock_dashboard/.venv/Scripts/streamlit.exe run C:/Directory/claude/fermi_dashboard/app.py --server.port 8502
```

독립 환경으로 분리하려면 `requirements.txt`로 새 venv를 만들면 된다.

SEC는 자동 요청에 연락처가 담긴 User-Agent를 요구한다. 기본값이 들어 있지만 바꾸려면:

```bash
set SEC_USER_AGENT="my-dashboard/1.0 (me@example.com)"
```

### 낡은 데이터를 화면이 스스로 알린다

핵심 판정 ①(계약 커버리지)의 분자·분모가 전부 수동 CSV라, 새 공시가 올라와도 화면은 옛 숫자를
그대로 보여준다. 그래서 `fundamentals.staleness()`가 **CSV 근거일 이후 접수된 8-K 계열 공시**를
세어 상단에 배너를 띄운다. 공시 피드는 이미 30분마다 자동으로 받으므로 추가 비용이 없다.

공시를 읽어보고 **바꿀 것이 없다고 판단한 경우**에는 아무 CSV도 바뀌지 않아 배너가 영원히 꺼지지
않는다. 그래서 `data/review_log.csv`에 검토 완료 지점을 따로 남기고, 기준일은 CSV 근거일과
검토 완료일 중 **더 늦은 쪽**을 쓴다.

```csv
reviewed_through,reviewed_at,verdict,note
2026-08-14,2026-08-15,변동 없음,8-K는 CEO 고용계약(Item 5.02)으로 계약·용량 수치 변동 없음
```

### 주간 자동 점검

주 1회(월요일 09:00 KST) 클라우드 루틴이 EDGAR 신규 공시를 읽고 무엇이 바뀌는지 보고한다.
클라우드에서 돌기 때문에 이 서버의 CSV를 직접 고치지는 못하고, 넣을 행을 그대로 제시한다.
설정은 https://claude.ai/code/routines 에서 바꾼다.

### 수동 CSV를 갱신해야 하는 시점

- **분기 실적 8-K가 나왔을 때** → `latest_reported.csv`. 이후 10-Q가 제출되면 XBRL이 같은 분기를
  덮으므로 그 행은 지워도 되고 두어도 무시된다(`append_manual`이 XBRL에 이미 있는 기간은 건너뛴다).
- **전력 용량·인허가 발표 시** → `power_stages.csv`
- **고객 계약 체결 시** → `contracts.csv`
- **증자·사채 발행 시** → `capital_events.csv`

각 행의 `source` 열에 근거 공시를 반드시 남긴다. 화면에도 그대로 표시된다.

## 구현 메모

**EDGAR의 누적 보고 문제.** companyfacts는 현금흐름·손익 항목을 회계연도 기초부터 누적(YTD)해서
담고, 같은 항목을 '분기 / 반기 누적 / 연 누적'으로 중복해서 싣는다. 그대로 쓰면 4분기 막대가
연간값이 되어 소진 속도가 몇 배로 부풀려진다. `sec_edgar.periodic_series()`가 같은 시작일을 공유하는
누적 묶음을 차분해 구간값을 만들고, 서로 겹치지 않는 가장 잘게 쪼갠 시계열을 골라낸다.

페르미는 2025년 Q2/Q3를 따로 보고하지 않은 항목이 있어 그 구간은 합산으로만 존재한다. 조용히 버리면
누적 합계가 어긋나므로(누적 capex가 $89M 모자란다) `25 Q2–Q3` 라벨을 달아 남기고, 소진 속도 같은
'분기당' 지표에는 `latest_quarter_value()`로 분기 하나짜리 구간만 쓴다.

**비교기업 T0 정렬.** 연도를 그대로 비교하면 의미가 없어, 각 사가 자본을 대규모로 확정 투입한 해를
T0으로 잡는다(연간 capex $100M 돌파, 미달 시 영업소진 $50M 돌파). LNG 기업은 이 값이 최종투자결정(FID)
연도와 그대로 일치한다. Core Scientific만 예외로 `peer_profiles.csv`의 `t0_override`를 쓴다 — 자동
판정은 2022년 비트코인 채굴 증설을 잡지만, 페르미와 구조가 같은 것은 계약을 먼저 확보하고 지은 2025년
AI 전환 사이클이다. 2022년 사이클은 계약 커버리지 비교용으로 별도 행에 남겼다.

**태그 교체.** 한 회사가 도중에 태그를 갈아타는 일이 흔하다. Applied Digital은 FY2023부터
`PaymentsToAcquirePropertyPlantAndEquipment`를 `PaymentsToAcquireProductiveAssets`로 바꿨다. 후보 태그
목록에서 첫 번째로 값이 잡히는 것만 쓰면 그 뒤 4개 연도가 통째로 비고, T0 판정이 2년 밀린다.
`refresh_peers.py`는 앞 태그를 우선하되 빈 연도만 뒤 태그로 채운다.

**중복 태그.** 총차입금이 `DebtCurrent` / `LongTermDebt` / `ShortTermBorrowings`에 같은 금액으로
중복 기재된다. 같은 시점 최대값을 채택한다(2026 Q1 $421.3M + Q2 순증 $98.8M = 8-K의 $520.1M과 일치).
같은 시점을 10-K와 이후 10-Q가 다르게 보고하는 재분류도 있어, 항상 최근 제출본을 쓴다.

**팔레트.** 차트 색은 라이트 서피스(`#fcfcfb`) 기준으로 색각 이상 분리도까지 검증한 값이다
(`theme.py`). aqua·yellow·magenta는 배경 대비가 3:1 미만이라 모든 막대에 값 레이블을 붙이고 차트마다
같은 값을 읽을 수 있는 표를 함께 둔다. `.streamlit/config.toml`에서 테마를 라이트로 고정한 이유도
이것이며, 배경색을 바꾸면 이 전제가 깨진다.
